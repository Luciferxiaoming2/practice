# ENDPAGE 熵析云枢打卡系统 — 技术文档

## 1. 系统概述

ENDPAGE 是一个企业级考勤打卡系统，支持 GPS 地点打卡、时间段验证、人脸识别三重校验。系统由三端组成，共用同一后端 API。

```
┌──────────────┐     ┌──────────────────┐     ┌───────────────┐
│  Web 管理端  │────▶│                  │◀────│  Flutter 移动端│
│  (Next.js)   │     │  FastAPI 后端 API │     │  (Android/iOS)│
│  端口: 3000  │     │  端口: 8000       │     │               │
└──────────────┘     └────────┬─────────┘     └───────────────┘
                              │
                     ┌────────▼─────────┐
                     │  SQLite 数据库    │
                     │  endpage.db      │
                     └──────────────────┘
```

## 5. API 接口设计

### 5.1 认证

所有需认证的接口通过 `Authorization: Bearer <JWT>` 头传递令牌。

**JWT Payload 结构：**
```json
{
  "sub": "1",                    // 用户 ID（字符串）
  "is_admin": true,              // 管理员标记
  "role": "管理员",               // 角色名称
  "role_id": 1,                  // 角色 ID
  "permissions": ["user.create"] // 权限代码列表
}
```

令牌有效期：**8 小时**

### 5.2 接口总览

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/auth/login` | 公开 | 登录，返回 JWT |
| POST | `/auth/register` | 公开 | 注册新用户 |
| GET | `/users/` | 认证 | 用户列表 |
| POST | `/users/` | 管理员 | 创建用户 |
| GET | `/users/{id}` | 认证 | 用户详情 |
| PATCH | `/users/{id}` | 认证(本人/管理员) | 更新用户 |
| DELETE | `/users/{id}` | 管理员 | 删除用户（级联删除打卡记录） |
| POST | `/users/{id}/reset-password` | 认证(本人/管理员) | 重置密码 |
| POST | `/users/{id}/reset-face` | 管理员 | 重置人脸（同时停用账户） |
| POST | `/checkins/` | 认证 | 打卡（服务端自动校验状态） |
| GET | `/checkins/` | 认证 | 打卡记录（支持日期筛选） |
| GET | `/roles/` | 管理员 | 角色列表 |
| POST | `/roles/` | 管理员 | 创建角色 |
| PATCH | `/roles/{id}` | 管理员 | 更新角色 |
| DELETE | `/roles/{id}` | 管理员 | 删除角色（系统角色不可删） |
| GET | `/roles/{id}/users` | 管理员 | 角色下的用户列表 |
| GET | `/roles/permissions` | 管理员 | 权限列表 |
| POST | `/face/enroll` | 认证 | 人脸录入（multipart 图片上传） |
| POST | `/face/verify` | 认证 | 人脸验证（multipart 图片上传） |

### 5.3 打卡状态校验逻辑

服务端在 `POST /checkins/` 时自动执行以下校验链，返回第一个失败的状态：

```
1. 地点校验（require_location=true 时）
   ├── Haversine 公式计算用户坐标与目标坐标的距离
   └── 距离 > location_radius → status = "location_fail"

2. 时间校验（require_time=true 时）
   ├── 获取当前服务器时间
   ├── 支持跨午夜时间段（如 22:00 ~ 06:00）
   └── 不在允许时间段内 → status = "time_fail"

3. 全部通过 → status = "ok"
```

## 6. 认证与授权体系

### 6.1 认证流程

```
[用户] ──登录──▶ POST /auth/login
                    │
                    ▼
              验证账号密码
                    │
                    ▼
              签发 JWT（含 sub, is_admin, role, permissions）
                    │
                    ▼
[Web] 存入 Cookie ← ──── JWT ────▶ 存入 SecureStorage [移动端]
                    │
                后续请求自动附带 Authorization: Bearer <token>
```

### 6.2 授权模型（RBAC）

```
权限 (Permission)
  例: user.create, user.update, checkin.view ...
       │
       ▼
角色 (Role) ── 多对多 ── 权限
  例: 管理员 → [user.*, checkin.*, role.*]
      普通用户 → [checkin.create, checkin.view]
       │
       ▼
用户 (User) ── 多对一 ── 角色
```

- 系统内置角色：`管理员`、`普通用户`（标记 `is_system=true`，不可删除）
- 管理员自动绕过权限检查
- `is_admin` 字段由角色自动同步（角色名为"管理员"时 is_admin=true）

### 6.3 路由守卫

| 端 | 实现方式 | 机制 |
|----|---------|----- |
| Web | `middleware.ts` | 解析 JWT payload，管理员 → `/dashboard`，普通用户 → `/user`，未登录 → `/login` |
| 移动端 | GoRouter `redirect` | 未登录 → `/login`，需设置 → `/setup/password`，已完成 → `/home` |

## 7. 人脸识别模块

### 7.1 技术方案

| 步骤 | 技术 | 说明 |
|------|------|------|
| 人脸检测 | OpenCV Haar Cascade | 内置级联分类器，无需外部模型 |
| 特征提取 | LBP 直方图 | 8x8 网格 Local Binary Pattern，生成 16384 维特征向量 |
| 特征比对 | 余弦相似度 | 阈值 0.6，≥0.6 判定为同一人 |
| 特征存储 | JSON 序列化 | 存入 users.face_embedding 字段 |

### 7.2 流程

**录入流程（移动端 → 后端）：**
```
拍照 → 上传图片 → POST /face/enroll
                     │
           ┌─────────▼──────────┐
           │ 1. 解码图片          │
           │ 2. Haar Cascade 检测 │
           │ 3. 裁剪人脸区域      │
           │ 4. LBP 直方图提取    │
           │ 5. L2 归一化         │
           │ 6. 存入 DB           │
           └─────────────────────┘
```

**验证流程（移动端打卡时）：**
```
拍照 → 上传图片 → POST /face/verify
                     │
           ┌─────────▼──────────┐
           │ 1. 提取新特征向量    │
           │ 2. 读取已存储特征    │
           │ 3. 计算余弦相似度    │
           │ 4. ≥ 0.6 → matched  │
           └─────────────────────┘
```

## 8. 前端架构

### 8.1 Web 管理端

**路由结构：**
```
/login                  # 登录
/register               # 注册
/dashboard              # 管理后台
  ├── /accounts         # 账户管理（增删改查 + 打卡规则配置）
  ├── /users            # 用户管理（同上 + 删除用户）
  ├── /checkins         # 打卡记录查询（支持用户/日期筛选）
  ├── /roles            # 角色权限管理
  └── /settings         # 系统设置
/user                   # 普通用户
  ├── /checkin          # GPS 打卡（高德地图）
  ├── /checkins         # 我的打卡历史
  └── /profile          # 个人资料
```

**API 客户端：**
- 基于 Axios，拦截器自动注入 JWT
- 401 响应自动清除 Cookie 并跳转登录页
- 所有接口方法集中在 `lib/api.ts`

**UI 组件体系：**
- 基础组件：Button、Input、Badge、Card（Tailwind + CVA）
- 业务组件：LocationPicker（地图选点+搜索）、AMapCheckin（打卡地图）
- 弹窗系统：统一 Modal 组件 + Framer Motion 弹簧动画
- 表单组件：Field（标签+错误提示）、Toggle（开关）、SelectField（下拉选择）

### 8.2 Flutter 移动端

**路由结构：**
```
/login                  # 登录
/register               # 注册
/setup/password         # 首次登录 - 修改密码
/setup/face             # 首次登录 - 人脸录入
/home                   # 打卡首页（GPS + 人脸验证）
/history                # 打卡历史
/profile                # 个人资料
```

**状态管理：**
| Provider | 职责 |
|----------|------|
| AuthProvider | 登录/注册/登出、JWT 管理、用户信息缓存 |
| CheckinProvider | 打卡操作、打卡记录查询 |

**离线支持：**
- JWT 持久化：FlutterSecureStorage
- 用户信息缓存：SharedPreferences（API 不通时回退）

**首次登录引导流程：**
```
注册/登录 → is_active=false?
              ├── Yes → /setup/password → 修改密码 → /setup/face → 人脸录入 → is_active=true → /home
              └── No  → /home
```
